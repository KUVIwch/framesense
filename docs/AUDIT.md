# Color Lab 产品化前审查

审查日期：2026-10-15。原版基线：`baseline-colorlab-20261014`，提交 `9e0ddde`。原有 51 项测试在改造前通过。基线与数据库备份由主开发流程保存，未改写已有 Git 历史。

## 已有功能与架构

FrameSense 已从早期在线模型原型转为离线桌面工具，实际 GUI 为 PySide6。NumPy/Pillow 处理图像，Pillow ImageCms 读取 ICC，colour-science 处理 Lab/OKLab/ΔE，rawpy 只在读取 ARW 时导入。学习模式为引导、练习、独立；SQLite 保存学习会话与复盘。已有全局统计、矩形对应区域、规则指导、结果对比和 Windows 打包路径。

这轮没有把旧设想当成既有功能：原版没有可靠的内容缓存、可取消的后台分析、稳定的缩放平移与状态恢复；GUI 测试主要验证构造和少量状态。原版也不是完整 RAW 显影器、语义分割器或摄影师参数反推器。

## 实际发现的问题

| 问题 | 影响 | 本轮核心处理 |
| --- | --- | --- |
| 两图独立缩放后直接相减 | 长宽比或尺寸不同会广播失败；同尺寸不同构图也被误当逐像素对应 | 改为 Lab 均值与分布比较，不要求场景对齐 |
| 全分辨率转 float、灰度、梯度；整块区域转 Lab | 24 MP 基准进程峰值约 1482 MiB | 加载与分析预览分离；统计最长边 1024、Lab/区域最长边 512 |
| 每次重新读图、重复直方图与转换 | 重复分析有明显等待 | 内容 SHA-256、算法版本和参数作键，线程安全 LRU，默认 128 MiB / 24 条 |
| 灰度使用 RGB 算术均值 | 同码值绿色与红色得到相同亮度，不能合理表达视觉权重 | 使用编码 sRGB 的 Rec.709 Y′ 权重，并注明其不是线性光亮度 |
| 高亮颜色仍使用暗端的 HSL 饱和度公式 | 高亮彩色的饱和度被低估 | 使用完整 HSL 分母 `1 - abs(2L - 1)` |
| 没有应用 EXIF 方向 | 竖幅照片显示、尺寸和区域坐标不一致 | 解码时应用 EXIF 转向，保留转向后的原始尺寸 |
| 完全越界的区域被压到末尾一列 | 可能把无效选择当作有效样本 | 使用半开区间边界；空、负尺寸和完全越界均拒绝 |
| 空明暗分区被当成中性 a*/b* | 对不存在的高光或暗部生成颜色建议 | 保存分区样本数，少于 16 个样本不生成分区色偏步骤 |
| 高光/阴影亮度滑块被描述为色相工具 | 工具与教学目标不符 | 分区颜色改用颜色分级色轮，物体局部改用蒙版 |
| 全图色偏直接推断白平衡 | 绿叶、天空、构图差别也会触发“纠正” | 事实、经验触发与试调建议分开；要求先核对可比中性材质 |

## 核心实现范围与边界

`AnalysisService` 是桌面应用共享的计算入口；Qt 后台任务和 UI 取消由界面层负责，服务不触碰控件。缓存锁避免相同照片并发解码，并串行保护缓存；取消不强杀正在执行的 NumPy、ICC 或 LibRaw 原生调用，界面层应丢弃过期结果。

JPEG 可用解码器的缩小解码；PNG 通常仍需读取完整压缩流再缩放。RAW 在实际请求时才导入 rawpy，可使用半尺寸 demosaic，之后限制预览尺寸；没有引入新的完整 RAW 编辑功能。没有真实 ARW 样本，因此本轮不能把异常格式测试等同于真实相机兼容性验证。

ICC 有效时转换到 sRGB，缺失时保留 assumed 标志，损坏时记录 `icc_error` 并回退。转换不能证明屏幕已经校准，也不能保留超出 sRGB 的全部颜色。单元测试覆盖有效 sRGB、损坏 ICC、LAB profile 转换、无配置和中文路径；不声称覆盖所有相机/广色域配置组合。

本报告仅记录代码审查与核心测量。界面布局、异步操作、持久化和打包的最终结果以对应文档及最终回归记录为准。
